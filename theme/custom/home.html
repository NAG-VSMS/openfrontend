Open Front End: HPC clusters on Google Cloud, from a web browser

The Open Front End (OFE) is a web interface for the Google Cloud Cluster Toolkit, formerly the HPC Toolkit. Administrators create Slurm clusters, networks and storage from a browser. Users install applications and submit jobs without writing Terraform or blueprints.

  • Open source, Apache 2.0
  • Part of the Cluster Toolkit repository
  • Slurm, Spack and Vertex AI Workbench

Developer Guide

How it works

The Front End runs on a single Compute Engine VM, the service machine. Everything below happens from its web interface once it is deployed.

  1. Deploy the service machine

    Run deploy.sh from a Linux, WSL or Cloud Shell client. Terraform creates the VM, a Cloud Storage bucket and a Pub/Sub topic, and installs Django, nginx and the Cluster Toolkit. The script finishes in about 15 minutes, then the software stack takes up to 15 more to come up.

  2. Register a credential and build the foundations

    Paste a service account key into the Credentials form. Create or import a VPC network and a Filestore filesystem. These have their own lifecycles and can be shared by several clusters.

  3. Create a Slurm cluster

    Name it, pick a subnet and zone, choose partitions and machine types. The Front End generates a Cluster Toolkit blueprint and runs the toolkit and Terraform for you. The cluster moves through creating and initialising to ready, with logs visible in the browser.

  4. Install applications and submit jobs

    Install applications through Spack, a custom build script, or by registering software already on the shared filesystem. Users then create jobs from an application page, pull input from a gs:// bucket, and get logs and outputs back in the web interface.

What you need to deploy it

On Google Cloud

A project with billing enabled and a user account that is a project Owner, or holds the smaller set of roles listed in the Admin Guide. The deploy script offers to enable the APIs it needs.

On your client machine

Linux, WSL or Cloud Shell with git, the Terraform CLI and the Google Cloud CLI installed, authenticated with gcloud auth application-default login.

Then three commands

# The Front End lives inside the Cluster Toolkit repository
git clone https://github.com/GoogleCloudPlatform/cluster-toolkit.git
cd cluster-toolkit/community/front-end/ofe
./deploy.sh

The script prompts for a deployment name, project, zone, optional DNS name and static IP, and an admin login. For unattended deployments, pass a YAML file with ./deploy.sh --config config.yaml.

Admin, 10 minutes

Network and storage

Under Credentials, paste the key the deploy script generated. Under Networks, create a VPC with one subnet in your region and apply cloud changes. Under Filesystems, create a Filestore instance in that subnet.

Admin, 15 to 20 minutes

A cluster with two partitions

Create a cluster, keep the default c2-standard-60 partition and add a second one for GPU or larger nodes. Authorise your users. Click Create and watch the status move to ready.

Cluster management
Admin then user

Install GROMACS, run a job

Under Applications, add a Spack application with spec gromacs and install it on a compute partition. A user then opens the application, clicks New Job, points the run script at an input set in a gs:// bucket and submits.

Spack installs

What is included

Slurm clusters

Controller, login nodes and partitions of any supported machine type, created and destroyed from the browser.

Spack application installs

Build from Spack recipes as a Slurm job on a compute node, or use custom scripts and manual registration.

Jobs with cloud storage I/O

Input from HTTP or gs:// URLs, output back to a bucket, logs uploaded on completion.

Benchmarks

Group runs of the same application and dataset to compare instance types and build options.

Vertex AI Workbench

JupyterLab notebooks with Python, TensorFlow, PyTorch or R images, mounted on cluster storage.

Google login and quotas

Users sign in with Google via OAuth2. Admins set per-user spend quotas before jobs can be submitted.

Networks and filesystems

Create VPCs and Filestore instances, or import existing ones, and share them across clusters.

Multi-project

Deploy in one project and provision resources in others by registering separate service account credentials.

Open source

Apache 2.0, developed in the Cluster Toolkit repository. Contributions welcome.

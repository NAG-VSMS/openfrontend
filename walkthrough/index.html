The idea

HPC on Google Cloud, for everyone who needs it

Open Front End puts a web portal in front of the Cluster Toolkit, so people get the HPC they want, when they want it.

  • Improves the ease of use of HPC on Google Cloud.
  • Puts power into the hands of all users, not only cloud specialists.
  • You concentrate on your workloads, not on the HPC.
  • Open source: ultimately, build the interfaces that work for you.
The engine · open source by Google

Curated, proven recipes

Every cluster starts from a Cluster Toolkit blueprint. Open Front End fills in the form; the toolkit does the building.

  • Blueprints and modules for networks, storage, Slurm and GPUs.
  • gcluster validates and expands every configuration before anything is created.
  • Terraform and Packer apply it. Nobody writes them by hand.
  • Applications packaged with Spack, ready to load as modules.
Starts from · compliant foundations

Built on compliant foundations

Open Front End deploys into your own Google Cloud project, under your organisation's policies, not beside them.

  • Runs in your project and your network.
  • Google sign-in, IAM and OS Login give every user one identity.
  • Desktops and portals sit behind Identity-Aware Proxy; machines need no public IP.
  • Customer-managed encryption keys where you require them.
Open Front End adds · user experience

Familiar tools, easy adoption

The tools HPC users already know, one click from the cluster page.

  • A guided wizard builds a cluster in eight steps.
  • A Linux desktop in the browser, on the login node or a visualization machine.
  • Open OnDemand for files, shells and jobs.
  • One Google sign-in across all of it.
Demo · cluster build

A cluster in eight guided steps

Name it, pick an account and a network, size the nodes, choose storage, review, create.

  • The tracker shows where you are; the summary fills in as you go.
  • Next waits until a step's required choices are made.
  • The account and the network can be set up automatically along the way.
  • Sensible defaults: most steps can be left as they are.

Open Front End adds · AI

Gemini, as a cluster advisor

Describe the workload in plain language. Gemini starts from a real blueprint and proposes changes for you to approve.

  • Ranked starting points, each with a reason and a match score.
  • It uses proven recipes: the AI does not hallucinate a cluster into existence.
  • Every proposal is built by the server and validated with gcluster expand.
  • A cost estimate for the compute, and answers to "how could I make this cheaper?"
Demo · cluster builder with Gemini

Watch the agent work

A three-minute recording with captions. Press play, or let autoplay run it.

  • You describe what you want.
  • Gemini looks things up with read-only tools.
  • It states the change as data; it never writes YAML.
  • The server builds deployment.yaml and validates it.
  • You review the diff and accept. Nothing is deployed from the chat.
